      Logic Apps calls the Function App API; I do not write the Function App’s underlying code. Payload values are illustrative placeholders because the API schema is business-specific.

      MY LOGIC APPS WORK

      Configure the call.
      Coordinate delivery.

      • Configure the scheduled Logic Apps trigger and assemble API payloads dynamically for business requirements.
      • Call the Function App API and handle its response in the workflow; the Function App’s underlying code is maintained separately.
      • Coordinate transfer of generated reports from Blob Storage to the required destination.
      • Prepare customer email content dynamically for the reporting requirement.

      SYSTEM BOUNDARIES

      ORCHESTRATIONAzure Logic AppsTrigger · request · status evaluation · file handoff · email
      API CALL↔
      PROCESSINGFunction AppIts own code generates reports in Blob Storage

      Blob Storage holds the generated reports. Logic Apps coordinates the later transfer and customer notification.

      OUTCOME & SCOPE

      Logic Apps evaluates the API’s PASS or FAIL business status. PASS continues the configured processing; FAIL follows configured business handling and dashboard tracking. An API FAIL does not automatically throw an Azure action exception. If an action fails inside Try, the shared Catch wrapper handles that separately.

      This describes one migrated workflow. Other workflows can use different triggers, processing steps, file handling and notifications.
