MIGRATION

Keep existing business behavior

Approximately 7–8 production workflows were migrated from Redpoint to Azure Logic Apps. Existing business logic was preserved and outputs reconciled to check expected behavior. New requirements are developed separately.

TRY / CATCH

Catch action-level failures

Each workflow’s Try scope contains its required actions, which may include SQL or API calls. If an action fails, the shared Catch scope runs its configured alert and dashboard failure logging.

STATUS LOGGING

Track workflow progress

Within Try, configured logging records workflow status for relevant actions or steps. Depending on the workflow, dashboard statuses include In Progress, Completed, Failed or Skipped. Placement varies by requirement.

BOUNDARY

API response PASS/FAIL evaluation is workflow-specific logic shown only in Case Study 1. It is separate from shared Catch handling for an Azure action failure.
